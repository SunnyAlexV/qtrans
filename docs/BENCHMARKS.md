# Benchmarks

Generated by `tools/benchmark.py` (run it to reproduce every number here; the protocol is in its
docstring). Each function is verified against Python before it is timed; its verification counts
(match / ill-conditioned / known / mismatch, over its hand-picked and random cases) are shown next to
the timings, so a speed-up is never quoted for a translation that differs.

## Machine and toolchain

- Linux 6.18.44-fc-v114 x86_64 (Intel(R) Xeon(R) Processor @ 2.80GHz); Python 3.13.16; NumPy 2.5.4; SciPy 1.18.1; g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
- compiled as: `/usr/bin/g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wdouble-promotion -ffp-contract=off -DQTRANS_LINALG_AUDIT -isystem/usr/include/eigen3` (`QTRANS_LINALG_AUDIT`: the backward-stability checks of linear algebra stay on while timed, as in every verification)
- 7 rounds per function, Python and C++ taking turns; medians, and the spread of the noisier side (slowest / fastest round - 1). This runs on a shared machine: a spread of tens of percent is the machine, not the code, and is why medians of several rounds are reported.

What this shows:

- Against a plain Python loop the C++ is 28× faster (`book_loop`) and 6× (`ytm_book`). Against NumPy-vectorised Python the gain is 2.4× (`book_numpy`): NumPy already runs its loops in C. The compiled loop is 1.8× faster than the vectorised Python.
- `mc_call` is slower in C++ (3.40 ms against 2.30 ms). Taken apart, the draws are on a par (1.27 ms against 1.51 ms), and `np.exp` is not (804.3 µs against 193.8 µs): NumPy has its own SIMD exp (AVX-512 on this CPU), and the C++ calls the C library's exp per element, so it agrees with Python's math.exp and only to rounding with NumPy's. Porting NumPy's exp would make it both faster and bit-identical on such CPUs; it is on the roadmap.
- Called from Python through `qtrans bind`, one scalar `bs_call` takes 255 ns against 50 ns in C++: the difference is Python's call and the conversions, and it is still 3× faster than the Python function. On the books of options and bonds the bound module is within 13% of the C++ alone: converting 10,000-element arrays is small next to the work.
